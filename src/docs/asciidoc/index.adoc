== 본인 탈퇴

현재 비밀번호를 확인한 뒤 계정을 `WITHDRAWN`으로 전환하고 모든 Refresh Session을 폐기한다.
이미 발급된 Access JWT는 별도 denylist가 없으므로 만료 시각까지 최대 15분 유효할 수 있다.
이미 `WITHDRAWN`인 계정의 재요청은 상태와 폐기 시각을 바꾸지 않는 `204 No Content`로 처리한다.

|`ACCOUNT_CURRENT_PASSWORD_MISMATCH`

|탈퇴할 수 없는 상태
|409
|`ACCOUNT_WITHDRAWAL_NOT_ALLOWED`

|마지막 이용 가능 SYSTEM_ADMIN
|409
|`ACCOUNT_LAST_SYSTEM_ADMIN`

== SYSTEM_ADMIN 계정 상태 변경

`SYSTEM_ADMIN`만 호출할 수 있다. 목표 상태는 `ACTIVE` 또는 `DISABLED`이며 사유는 필수다.
`ACTIVE`에서 `DISABLED`, `DISABLED`에서 `ACTIVE` 전이만 허용한다.
로그인 잠금은 계정 상태와 별개이며 전용 잠금 해제 API로 처리한다.
동일 상태 요청은 감사 기록과 Refresh Session 폐기 없이 멱등한 `204 No Content`로 처리한다.
실제 `DISABLED` 전이만 Refresh Session을 폐기하며 모든 실제 전이는 영속 감사 기록을 남긴다.
이미 발급된 Access JWT는 즉시 폐기하지 않으며 기존 `exp`까지 최대 15분간 유효할 수 있다.

[cols="2,1,3"]
|===
|상황 |HTTP |오류 코드

|Access JWT 누락·오류
|401
|`AUTH_AUTHENTICATION_REQUIRED`

|JWT의 SYSTEM_ADMIN 권한 부족
|403
|`AUTH_ACCESS_DENIED`

|DB 기준 관리자 권한·상태 상실
|403
|`ACCOUNT_ADMIN_OPERATION_NOT_ALLOWED`

|목표 상태 누락·null
|400
|`COMMON_INVALID_REQUEST`

|허용하지 않은 목표 상태
|400
|`COMMON_MALFORMED_REQUEST`

|잘못된 변경 사유
|400
|`COMMON_INVALID_REQUEST`

|대상 계정 없음
|404
|`ACCOUNT_NOT_FOUND`

|자기 자신 비활성화
|409
|`ACCOUNT_SELF_DISABLE_NOT_ALLOWED`

|허용되지 않은 상태 전이
|409
|`ACCOUNT_STATUS_TRANSITION_NOT_ALLOWED`
|===

== 이메일 OTP v2

이메일 OTP Challenge는 이메일과 목적에 귀속되며 한 번만 소비할 수 있다.
발급 API는
`Cache-Control: no-store`와 `challengeId`, `expiresInSeconds`를 반환한다. `code`는 숫자 6자리이고 `challengeId`는 UUID이다.

[cols="1,3,2,2"]
|===
|Method |Path |인증 |성공

|`POST`
|`/api/v2/auth/signup/email-otp`
|Frontend Basic
|`202 Accepted`

|`POST`
|`/api/v2/auth/signup`
|Frontend Basic
|신규 가입 `201 Created`, 탈퇴 계정 복구 `200 OK`

|`POST`
|`/api/v2/users/me/password/email-otp`
|Bearer JWT
|`202 Accepted`

|`PATCH`
|`/api/v2/users/me/password`
|Bearer JWT
|`204 No Content`

|`POST`
|`/api/v2/auth/password-reset/email-otp`
|Frontend Basic
|`202 Accepted`

|`PATCH`
|`/api/v2/auth/password-reset`
|Frontend Basic
|`204 No Content`
|===

=== 이메일 OTP 오류

[cols="1,3,4"]
|===
|HTTP |code |조건

|`400`
|`EMAIL_VERIFICATION_INVALID_CHALLENGE`
|Challenge가 없거나 만료·소진됨, 또는 이메일·목적·인증번호가 일치하지 않음

|`400`
|`AUTH_PASSWORD_RESET_INVALID`
|비밀번호 재설정 계정·상태 또는 Challenge 정보를 외부에 구분하지 않는 일반화된 거절

|`409`
|`EMAIL_VERIFICATION_ISSUE_SUPERSEDED`
|동시 새 발급으로 현재 발급 요청이 대체됨

|`429`
|`EMAIL_VERIFICATION_COOLDOWN_ACTIVE`
|정규화 이메일의 공유 쿨다운 중이거나 메일 사업자가 요청을 제한함. `Retry-After` 포함

|`503`
|`EMAIL_VERIFICATION_DELIVERY_UNAVAILABLE`
|메일 사업자·네트워크·시간 제한 실패 또는 응답 전에 Challenge가 만료됨
|===

== Learning 후보 계정 검색

`POST /api/v1/internal/accounts/search`는 Learning Service HTTP Basic Credential을 사용하는 내부 API다.
Learning이 `candidateIds`에 같은 기수의 ACTIVE 멤버십 중 현재 재실인 계정만 넣고,
Identity는 그 범위에서 이름 또는 이메일을 부분 검색한 뒤 최대 20건을 반환한다.
`query`는 앞뒤 공백을 제거하며 빈 문자열은 허용하지 않고 최대 100자다. `%`, `_`, `!`는 LIKE 와일드카드가 아닌 문자 그대로 검색한다.
`candidateIds`는 내부 일괄 계정 조회 API와 동일하게 요청당 최대 100개이며, 중복 ID는 한 번만 검색한다.
